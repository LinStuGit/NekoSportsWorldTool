# Android APK 设计

## 已确认需求

- 面向 Android 16；暂按 ARM64 手机制作，可另构建模拟器版本用于验证。
- 保留全部现有功能及 egui 界面风格，适配竖屏、触控与软键盘。
- 仅要求 App 打开并位于前台时可用，不增加后台服务、后台调度或锁屏运行保证。
- 调用手机当前默认输入法；支持中文组合输入、密码隐藏和键盘收起。
- 用户启动的长任务运行期间保持屏幕常亮，任务结束后释放；切到后台不持有唤醒锁。

## 实施方案

Rust 业务层继续共用。增加 Android 库入口与薄 Java NativeActivity 外壳；电脑端 main 仍保留。Android 构建采用 SDK/NDK、Rust Android target，产物为独立可安装 APK。

现有 eframe/winit 的 NativeActivity 文本输入不作为中文输入的可靠前提：Android 文本框点击后使用原生 EditText 编辑层及系统默认输入法，确认后回填到原有 egui 字段。原生控件负责选区、组合输入、密码模式、粘贴以及键盘避让。数值字段保持原操作并提供可触控的原生输入入口。桌面文本编辑行为保持原样。

屏幕常亮由 Activity Window 标志控制，状态由 Rust 的用户任务运行标志驱动，不使用后台服务。数据目录由 Android internal_data_path 注入，所有会话、配置、设备标识和缓存留在应用私有目录。电脑端继续使用可执行文件目录。APK 不包含当前工作区的真实会话、账号配置或设备标识。

字体采用可再分发中文字体并附许可证；Android HTTPS 使用明确的受信根证书来源，不关闭证书验证。页面按手机宽度折行、滚动，保留七个功能入口及所有操作。

采用 Android 16 API 36 为目标，并检查原生库 ELF 与 APK 的 16 KB 对齐。先交付本地签名 APK；不涉及应用商店发布。构建脚本记录工具链及签名位置，密钥不入库。

## 验收

1. 电脑端既有离线测试通过；GUI 编译通过。
2. Android ARM64 APK 构建、签名验证和对齐检查通过。
3. 可用模拟器/设备上验证启动、七页面、键盘输入和收起、中文显示、应用私有文件保存、长任务常亮标志。
4. 真实登录或会产生服务器状态变更的业务操作由用户在真机验证；测试不自动使用电脑中的凭据。
5. 明确区分编译验证、模拟器验证和真机验证，未验证内容如实列出。
